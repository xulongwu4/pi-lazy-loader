# Review Resolution: `v0.2.1...HEAD` (v0.3.0 Release)

This document maps every finding from `reviews/v0.2.1-to-head.md` to its concrete code resolution, verification checks, and recorded evidence.

## Standards Axis

### 1. Duplicated Manifest Traversal & Validation (`src/command-config.ts:64, 258`)
- **Finding**: Manifest commands independently traversed and validated during schema validation and merge, allowing drift.
- **Resolution**: Implemented `normalizeManifestCommands(entries: ManifestEntry[])` in `src/command-config.ts`. It traverses entries once, validates names, descriptions, intra-package duplicates, and cross-package collisions, returning `ValidatedBuiltinCommands` (`builtinMap`, `packageToSource`, `diagnostics`). Both `validateManifestCommands` and `mergeCommandDefinitions` consume this shared normalized representation without duplicate loops.
- **Files**: `src/command-config.ts`.
- **Checks & Evidence**: `checks/command-proxy-checks.ts` Check 1 & Check 4 pass.

### 2. Divergent Responsibilities in Command Config (`src/command-config.ts:109, 427, 488`)
- **Finding**: `src/command-config.ts` combined schema validation, merge policy, file reading, and display/description formatting.
- **Resolution**: Extracted presentation formatting into a dedicated module, `src/command-presentation.ts`, defining `formatTargetDisplay`, `formatStartupDescription`, and `formatPostLoadDescription`. `src/command-config.ts` strictly handles configuration parsing, validation, and merging.
- **Files**: `src/command-presentation.ts`, `src/command-config.ts`, `index.ts`, `src/loader.ts`.
- **Checks & Evidence**: `checks/command-proxy-checks.ts` Check 4 & 5 pass; unit tests format descriptions through the new module.

### 3. Data Clumps in Command Description Shapes (`src/command-config.ts:508, src/loader.ts:280`)
- **Finding**: Package name, command name, descriptions, and target labels traveled together in ad-hoc object shapes.
- **Resolution**: Defined a shared interface `CommandDescriptionContext` in `src/command-presentation.ts` (`{ packageName, commandName, declaredDescription?, description?, targetLabel? }`). `MergedCommandDefinition` in `src/command-config.ts` extends this interface. `ReserveCommandOptions` and `LazyLoader` use it directly when preparing post-load description handoff.
- **Files**: `src/command-presentation.ts`, `src/command-config.ts`, `src/loader.ts`.
- **Checks & Evidence**: Type checks pass cleanly (`tsc --noEmit`); post-load attribution verified in Check 5.

### 4. Duplicated Fixture Construction (`checks/command-proxy-checks.ts:348, 482, 564`)
- **Finding**: Three tests repeated temporary package directory creation, package.json/index.js generation, mock Pi construction, and cleanup.
- **Resolution**: Extracted `createMockPackageFixture(options: MockPackageFixtureOptions)` in `checks/command-proxy-checks.ts`. It encapsulates directory creation, mock Pi setup, and `cleanup()`. Used across Checks 5, 6, and 7 without introducing an external test framework.
- **Files**: `checks/command-proxy-checks.ts`.
- **Checks & Evidence**: `bun checks/command-proxy-checks.ts` passes all 8 checks.

### 5. Duplicated `CommandProxyDeclaration` Definition (`src/command-config.ts:12, src/manifest.ts:3`)
- **Finding**: `CommandProxyDeclaration` interface was defined identically in both `manifest.ts` and `command-config.ts`.
- **Resolution**: Defined `CommandProxyDeclaration` once in `src/manifest.ts`. Imported and re-exported from `src/command-config.ts`.
- **Files**: `src/manifest.ts`, `src/command-config.ts`.
- **Checks & Evidence**: `tsc --noEmit` validates single source of type definition.

### 6. Unused Speculative State `hasEmptyDesc` (`src/command-config.ts:279, 306, 313`)
- **Finding**: `hasEmptyDesc` was maintained in user command maps but never read.
- **Resolution**: Removed `hasEmptyDesc` from the user package command map and loop.
- **Files**: `src/command-config.ts`.
- **Checks & Evidence**: `tsc --noEmit` and `checks/command-proxy-checks.ts` Check 4 pass.

### 7. Primitive Obsession in Command Identity (`src/loader.ts:172, 189, 271`)
- **Finding**: Colon-delimited key interpolation (`${manifest.name}:${commandName}`) was repeated across loader methods.
- **Resolution**: Refactored `capturedCommands` into a nested map (`Map<string, Map<string, any>>`) with helper methods `getCapturedCommand`, `setCapturedCommand`, and `hasCapturedCommand`. Eliminated string concatenation entirely.
- **Files**: `src/loader.ts`.
- **Checks & Evidence**: `checks/phase4-command-checks.ts` and `checks/command-proxy-checks.ts` Check 5–7 pass.

### 12. Duplicate Target Registration Diagnosis and Atomic Rollback
- **Finding**: Test Matrix required `duplicate target registration diagnosed`, but `src/loader.ts` silently overwrote `stagedRegistrations.set(name, command)` on duplicate registrations for the same reserved `(package, command)`.
- **Resolution**: Updated `src/loader.ts` command proxy in `loadSingleEntry`:
  - If a reserved command registration is encountered and `stagedRegistrations` already contains `name` (or `capturedCommands` already contains it), package loading aborts immediately with an actionable error identifying both package and command: `Duplicate target registration for command "${name}" in package "${packageName}"`.
  - Atomicity guaranteed: because package loading aborts prior to the staged commit loop, zero staged commands are committed to `capturedCommands`, `pi.registerCommand` is never called for target commands, and the original startup stub registered on `pi` remains completely intact.
  - Added deterministic tests in `checks/command-proxy-checks.ts` (Check 6.2 and Check 6.3) covering duplicate registrations within a single factory and across multiple extension entries (`entry1.js`, `entry2.js`).
- **Files**: `src/loader.ts`, `checks/command-proxy-checks.ts`.
- **Checks & Evidence**: `bun checks/command-proxy-checks.ts` Check 6.2 & 6.3 pass deterministically; verified that prior to the `src/loader.ts` fix the check failed as expected.
